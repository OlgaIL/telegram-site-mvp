# Оформление и попап входа: подготовка публикации

Обновлено 25.10.2026. Публикацию выполняет Ольга. Агент ведёт её по одному шагу и ждёт результат. Этот документ не разрешает агенту выполнять серверные команды.

## Что готово локально

- Главная, общие стили, адаптивность и компактный попап входа.
- Прямой /login сохранён для callback и прямых переходов; email/сессии на сервере не переписывались.
- Общие окна cookie/условий беты; это ещё не готовые политика и соглашение (L-01 открыта).
- Зависимости и миграции не менялись. Успешный email-релиз 7f4cc7f повторно не настраивать.

## До изменения production

1. Метрика: счётчик 113788018 предоставлен Ольгой 25.10; локальная интеграция подготовлена, Вебвизор включён согласно присланному коду. Уведомление обновлено, чувствительные элементы скрыты. После публикации проверить настоящий визит и SPA-переходы в отчётах. Localhost/preview не отправляют визиты. Цели и окончательные тексты политики отдельно.
2. Яндекс: 25.10 Ольга подтвердила настоящий production-вход и возврат в /add-channel после выхода/повторной авторизации. После перезапуска выполнить короткую регрессионную проверку, настройки приложения повторно не менять.
3. VK в этом релизе оставляем выключенным; доработка и реальный тест идут отдельно. На production кнопка отсутствует. Не менять VK_AUTH_ENABLED на true.
4. Открытые задачи L-01/L-02 (тексты, контакт, право на канал) остаются в плане до приглашения внешних клиентов; текущая публикация оформления не означает завершение этих задач. Окна с информацией не заменяют документы.
5. Подтвердить финальный коммит, успешные тесты и сборку; затем отправить ветку codex/email-auth в origin (до публикации на сервер).

## Когда Ольга скажет готовить публикацию

1. Ольга открывает SSH root@147.45.246.205 и /var/www/tg4you.ru/app. Сначала только git status --short и git log -1 --oneline; при изменениях остановиться, ничего не сбрасывать.
2. Зафиксировать предыдущую ревизию и рабочую конфигурацию, убедиться в резервной копии. Не менять процессы Word2you.
3. Получить origin/codex/email-auth, сверить целевую ревизию. Не подменять эту ветку main.
4. Собрать клиент: npm run build --prefix client. Текущий блок не требует повторной настройки SMTP или новых миграций; при добавлении к релизу других изменений пересмотреть список.
5. Только после успешной сборки перезапустить tg4you-api и tg4you-web с --update-env, сохранить PM2.
6. Ольга проверяет health, главную, мобильную версию, настоящий канал и фото, попап, email-вход, Яндекс/VK согласно согласованному набору, возврат к заявке, кабинет и выход. Проверить визит в Метрике и работу согласованных целей.
7. При проблемах вернуться к сохранённой ревизии, пересобрать клиент и перезапустить только tg4you-процессы. Схему БД разрушительно не откатывать.
