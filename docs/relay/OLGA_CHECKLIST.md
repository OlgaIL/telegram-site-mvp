# Чек-лист Ольги — «Telegram Зеркало», приёмник

Порядок сверху вниз. У каждого шага: где выполнять, что сделать, как проверить.
Пометки площадок: **[WIN]** — PowerShell на своём компьютере; **[ПРИЁМНИК]** — новый сервер, Linux; **[ПРОД]** — VPS в РФ, Linux; **[БРАУЗЕР]** — панель провайдера или сервиса; **[TELEGRAM]** — приложение Telegram.

Заглушки в угловых скобках заменяются своими значениями. **Ни одно секретное значение не отправляется в чат, в Git и агенту.**

## Что секретно, а что нет

| Значение | Секретно | Где живёт |
|---|---|---|
| Токен основного бота `<MAIN_BOT_TOKEN>` | **Да** | После переключения — только `/etc/tg4you-relay/relay.env` на приёмнике |
| Токен тестового бота `<TEST_BOT_TOKEN>` | **Да** | Локальный `.env` для тестов; на приёмнике — на время опытов |
| Секрет подписи `<RELAY_INGEST_SECRET>` | **Да** | `relay.env` на приёмнике и `.env` backend на проде |
| `DATABASE_URL`, пароли SMTP, секреты OAuth | **Да** | Только `.env` на проде, как сейчас |
| Закрытый SSH-ключ `tg4you_relay` | **Да** | Только свой компьютер |
| Адрес сигнала healthchecks `<HEALTHCHECK_PING_URL>` | **Да** (кто знает адрес, может подделать «жив») | `relay.env` |
| Открытый SSH-ключ `tg4you_relay.pub` | Нет | Панель провайдера |
| IP приёмника `<RELAY_IP>` | Нет, но без нужды не публиковать | — |
| Имена ботов, адрес сайта, идентификатор ключа `k1` | Нет | — |

Агенту можно: доступ к репозиторию и локальной базе на своём компьютере. Агенту не нужно и не даётся: SSH на прод, токены ботов, `.env` прода, доступ к панели провайдера.
SSH на приёмник агенту — только отдельным решением и отдельным ключом; по умолчанию все команды на серверах выполняешь сама.

## Шаг 5. Сервер для опыта (один раз; покупка — только после шага 0)

**[БРАУЗЕР]** Timeweb Cloud → Облачные серверы → Создать:
- регион: **Нидерланды**;
- тариф: **NL-15** (1 vCPU, 1 ГБ, 15 ГБ, с публичным IPv4) — 1 820 ₽/мес на 15.11.2026, списание почасовое, около 2,5 ₽ в час;
- система: Ubuntu 24.04;
- вход: по SSH-ключу (ниже), пароль не задавать;
- резервные копии: пока не включать;
- пополнение баланса: минимум 500 ₽.

Перед оплатой сверить цену в корзине с этой. Отличается — остановиться.
Сервер в отдельном проекте панели, чтобы случайно не задеть основной VPS.

**[WIN]** Ключ создаётся один раз:

```powershell

```

```powershell
Get-Content "$env:USERPROFILE\.ssh\tg4you_relay.pub"
```

Вторую команду — её вывод (открытый ключ) вставить в панель при создании сервера.

Проверка:

```powershell

```

Ответ со словом `Linux` — вход работает.

## Шаг 10. Секрет подписи (один раз; повторяется при ротации)

**[ПРИЁМНИК]**

```bash
openssl rand -hex 32
```

Вывод — это `<RELAY_INGEST_SECRET>`. Скопировать его в менеджер паролей. Внести в два места:

| Куда | Строка |
|---|---|
| **[ПРИЁМНИК]** `/etc/tg4you-relay/relay.env` | `RELAY_INGEST_KEY_ID=k1` и `RELAY_INGEST_SECRET=<RELAY_INGEST_SECRET>` |
| **[ПРОД]** `/var/www/tg4you.ru/app/.env` | `RELAY_INGEST_KEYS=k1:<RELAY_INGEST_SECRET>` |

Остальные строки `relay.env`: `BOT_TOKEN=<токен>`, `INGEST_BASE_URL=https://tg4you.ru`, `RELAY_DATA_DIR=/var/lib/tg4you-relay`, `HEALTHCHECK_PING_URL=<адрес сигнала>`.
Права на файл:

```bash
chmod 600 /etc/tg4you-relay/relay.env
```

## Шаг 11. Релиз, фаза 1 — тестовый бот (по `docs\relay\RELEASE.md`)

1. **[ПРОД]** записать состояние: `pm2 list`, ответ Word2you.

5. **[ПРИЁМНИК]** установить службу скриптом `install.sh`, в `relay.env` — токен **тестового** бота, запустить.
6. **[TELEGRAM]** пост с текстом и пост с фото в `@test_site_tele`.
