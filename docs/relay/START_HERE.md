# Инструкция для ИИ-помощника Ольги: разобрать с ней план «приёмник Telegram»

Этот файл целиком — твоё задание. Отвечай Ольге по-русски, простыми словами.

Задание необязательное. Оно нужно, если Ольга уже прочитала `SUMMARY.md` и хочет перед решением проверить разбор по своему коду.
Ты только читаешь и отчитываешься: ни один файл проекта и ни один из этих документов не меняется.

## Контекст

Ольга делает проект «Telegram Зеркало» (https://tg4you.ru, репозиторий `C:\Users\olgak\PROJECTS\telegram-site-mvp`).
Публикации из Telegram перестали доходить до сайта: webhook от Telegram не достигает сервера в РФ.
Внешний архитектор по её заданию подготовил разбор, план и задания разработчикам. Они лежат в той же папке, что и этот файл,
и пришли pull request «Add Telegram relay research, plan and agent prompts» в ветку `codex/email-auth`. Он ещё не слит.
Ты читаешь их из отдельной папки (git worktree), рабочая копия Ольги при этом не меняется.

Чего архитектор не видел и не делал: production-сервер, базу, ботов и рабочую копию Ольги. Код он читал
по GitHub на коммите `32f72a7` (ветка `codex/email-auth`) и не запускал. Всё про сервер он знает со слов задания.

## Задача

Помочь Ольге понять план, сверить его с действительностью и принять решения. **Не внедрять.**

## Что прочитать, в этом порядке

1. `SUMMARY.md` — суть на одну страницу.
2. `ANALYSIS.md` — полный разбор: доказательства, варианты, архитектура, эксперимент, смета, риски.
3. `PLAN.md` — этапы, проверки, откат.
4. `OLGA_CHECKLIST.md` — шаги Ольги.
5. `CONTRACT_DRAFT.md` и `prompts\00_COMMON.md` — бегло, чтобы понимать, что получат разработчики.

Файлы `prompts\01_…06_…` сейчас читать не нужно.

## Что сделать

1. **Сверить разбор с репозиторием.** В рабочей копии Ольги, только чтением: какая ветка и коммит сейчас,
   есть ли незакоммиченные изменения, отличается ли код Telegram-цепочки от `32f72a7`.
   Проверить десять находок из раздела 1 разбора: для каждой — «подтверждается / не подтверждается / изменилось» и `файл:строка`.
2. **Объяснить Ольге** своими словами, в 10–15 строк: что случилось, что предлагается, сколько стоит, что потребуется от неё.
3. **Задать четыре вопроса** из раздела 0 разбора, по одному, и записать ответы дословно.
4. **Найти, где план не сходится с действительностью.** Спросить у Ольги то, чего нет в документах: какая ветка на production,
   как она выкатывает релизы, что ещё живёт на сервере, есть ли уже клиенты и какие у них каналы.
   Отметить каждое место, где план опирается на неверное предположение.
5. **Записать отчёт** в файл `reports\00_review_<модель>.md` рядом с этим файлом (вместо `<модель>` — твоё название):
   - состояние репозитория (ветка, коммит, что изменено);
   - таблица по десяти находкам;
   - ответы Ольги на четыре вопроса;
   - расхождения плана с действительностью;
   - вопросы автору разбора;
   - решение Ольги: идём по плану / идём с изменениями (какими) / не идём.
6. **Сказать Ольге следующий шаг** одной строкой. Если она решила идти — это шаги 1 и 2 чек-листа (шаг 2 — слить pull request).
   Отчёт лежит в отдельной папке и в Git не попал: сказать Ольге его полный путь.

## Запреты

1. Ничего не покупать и не создавать у провайдеров.
2. Не подключаться к production, не выполнять серверные команды, не трогать Word2you.
3. Не менять настройки ботов: никаких `setWebhook`, `deleteWebhook`, `getUpdates` ни у основного, ни у тестового бота.
4. Не править код, не создавать миграции, не переключать ветку, не коммитить и не делать push без прямого слова Ольги.
   Документы в этой папке не править, не переименовывать и не удалять. Единственный файл, который ты создаёшь, — отчёт.
5. Не выполнять задания из `prompts\01_…06_…`: они запускаются позже, по одному, после решения Ольги.
6. Не просить у Ольги токены, пароли, `.env` и не читать файлы `.env`.
7. Pull request не сливать и не закрывать: это решение и действие Ольги.

## Расход

Объём чтения — около 900 строк в пяти файлах плюс файлы Telegram-цепочки в `server\`. Субагенты не нужны.
Вывод команд в чат — не больше 100 строк.

## Критерий завершения

Отчёт записан, в нём есть ответы на четыре вопроса и решение Ольги; Ольга знает свой следующий шаг.
Если Ольга не готова решать сейчас — записать, каких сведений ей не хватает, и остановиться.
