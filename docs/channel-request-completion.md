# Подключение канала по заявке

Сценарий для проверки после ручной публикации:

1. Создайте тестовый Telegram-канал и отправьте на сайте заявку на его подключение.
2. На странице после заявки найдите инструкцию и имя сервисного бота.
3. Добавьте бота администратором канала и опубликуйте **новый** текстовый пост.
4. Под админской учётной записью откройте `/admin/channel-requests`. Найдите
   номер заявки и обнаруженный канал. Если `@username` совпадает, канал будет
   предложен; для приватного канала выберите его из списка вручную. Сверьте
   название и Telegram ID перед подтверждением.
5. Нажмите «Подключить канал». Адрес сайта создастся автоматически; ссылка
   появится в админке и кабинете пользователя. Откройте её и проверьте пост.

Почтовое уведомление пока не настроено. Реальные `.env` не выводите и не
передавайте в переписке.

Перед проверкой убедитесь, что для Next.js задано реальное
`NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`; после изменения значения пересоберите клиент.

## Запасной сценарий через терминал

Этот сценарий выполняет один оператор после того, как сервисный бот добавлен
администратором в канал и webhook получил хотя бы один `channel_post`.

1. В служебной странице заявок найдите номер заявки.
2. По логу webhook или локальной БД получите числовой `telegram_chat_id` уже
   обнаруженного канала. Не используйте username вместо chat id.
3. Выберите уникальный slug: только строчные латинские буквы, цифры и дефисы.
4. Из корня репозитория запустите:

```powershell
npm.cmd run channel:complete -- --request-id 123 --telegram-chat-id -1001234567890 --slug my-channel
```

Скрипт в одной транзакции проверяет заявку и обнаруженный канал, создаёт сайт,
помечает заявку как `done` и привязывает к ней сайт. Если сайт для канала или
привязка к заявке уже существуют, изменений не будет. Успешный результат —
`Done: /site/my-channel`.

Сначала примените миграции:

```powershell
npm.cmd run db:migrate
```
